# Адаптивность и доступность: рабочий стандарт

Этот файл задаёт минимальные требования для новых блоков и изменений сайта. Цель — не отдельные макеты под модели устройств, а читаемый и управляемый интерфейс во всём диапазоне ширин.

## Принцип

Проектируем от узкого экрана к широкому. Брейкпоинт появляется, когда текущая композиция перестаёт работать: пункты навигации не помещаются, строка становится слишком длинной, карточки теряют читаемость. Не привязываем брейкпоинты к названиям устройств и их физическому разрешению — важна ширина viewport в CSS-пикселях.

Для основного контента не допускается горизонтальная прокрутка на ширине 320 CSS px. Исключение — элементы, которым по смыслу нужны две оси: карты, чертежи и сложные таблицы. Их прокрутка должна быть локальной, заметной и не мешать прокрутке страницы.

## Обязательная матрица проверки

| Сценарий | Ширина viewport, CSS px | Требование |
| --- | ---: | --- |
| Узкий экран и масштабирование | 320 | Обязательно |
| Типичный Android | 360 | Обязательно |
| Типичный iPhone | 390 | Обязательно |
| Планшет, портретная ориентация | 768 | Обязательно |
| Планшет горизонтально / небольшой ноутбук | 1024 | Обязательно |
| Ноутбук | 1280 | Обязательно |
| Рабочий десктоп | 1440 | Обязательно |

Дополнительно, если есть время или это оправдано аналитикой аудитории: 375, 412–430, 1920 и 2560+ px. Для больших экранов отдельный макет не нужен: достаточно проверить, что ограничение ширины контейнера сохраняет читаемую длину строки и не оставляет композицию «разъехавшейся».

Проверять нужно не только контрольные точки, но и промежуточные ширины между ними. Фиксированный набор макетов не заменяет плавную адаптацию.

## Чек-лист перед передачей или публикацией

### Компоновка

- На 320 px нет горизонтальной прокрутки страницы, обрезанного текста, картинок и контролов.
- Навигация меняет вид до того, как пункты начинают конфликтовать; мобильное меню доступно с клавиатуры.
- Карточки, таблицы и графика сохраняют смысл. Сложные таблицы получают локальную прокрутку или альтернативное представление.
- На 1280–1440 px текстовый контейнер не становится слишком широким, а на 1920 px не растягивается без причины.
- В портретной и ландшафтной ориентации телефона основной сценарий остаётся доступным.

### Текст, управление и доступность

- Основной текст читаем без увеличения; размеры и интервалы не зафиксированы так, чтобы ломаться при пользовательском увеличении шрифта.
- На 400% масштабе браузера ключевой контент остаётся доступным без горизонтальной прокрутки страницы; это практическая проверка требования WCAG Reflow.
- Все действия доступны клавиатурой; видимый фокус не перекрывается и следует логическому порядку.
- У интерактивных элементов есть понятное имя; у полей форм — постоянная подпись, понятная ошибка и связь ошибки с полем.
- Состояния не различаются только цветом. Контраст обычного текста — не ниже 4,5:1.
- Целевая зона нажатия у основных кнопок и ссылок — около 44×44 CSS px; минимальная допустимая цель для WCAG 2.2 AA — 24×24 CSS px с установленными стандартом исключениями.
- Действия, доступные по наведению, доступны также касанием и клавиатурой.

### Мобильная среда и производительность

- Проверить ключевые сценарии в Safari на iOS и Chrome на Android, а не только в эмуляторе браузера.
- Полноэкранные блоки не скрывают кнопку под адресной строкой или вырезом экрана: при необходимости использовать динамическую высоту viewport (`dvh`) и safe-area inset.
- Изображения отдаются в подходящем размере и не заставляют мобильный браузер скачивать десктопный файл без необходимости.
- Проверить загрузку на мобильной сети и отсутствие заметных сдвигов макета при появлении шрифтов, изображений и графики.

## Техническая основа

- В документе есть `<meta name="viewport" content="width=device-width, initial-scale=1">`.
- Размеры и сетки по возможности гибкие: `minmax()`, `clamp()`, flex/grid, относительные размеры и ограничение `max-width`; не строить страницу на фиксированной ширине блоков.
- Не отключать масштабирование пользователя через `user-scalable=no` или `maximum-scale=1`.
- При существенных изменениях пройти ручной чек-лист выше и автоматическую проверку доступности; автоматический инструмент не заменяет ручную проверку клавиатурой и реальным устройством.
