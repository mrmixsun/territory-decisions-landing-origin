# Изометрическая иллюстрация: инструкция для следующего агента

Эта инструкция описывает актуальную иллюстрацию первого экрана сайта. Перед изменениями прочитайте её вместе с инструкциями проекта и проверьте состояние рабочей копии. Прототипы и незакоммиченные файлы могут принадлежать пользователю: не удаляйте и не перезаписывайте их без необходимости.

## Что сохранять

- Иллюстрация — редактируемая SVG-сцена с отдельными объектами, а не растровая картинка. Она находится справа, заполняет блок по высоте и плавно исчезает под текстом слева.
- Шесть ключевых объектов: существующий ЖК, школа, детский сад, многоуровневый паркинг, парк и общественное пространство, проектируемый ЖК. Они выделены цветом уже при открытии страницы.
- По умолчанию карточка скрыта. При наведении на объект появляется карточка **рядом с ним**, при уходе курсора исчезает. Клик не выполняет действия. Не меняйте эту логику без отдельной просьбы.
- Дома, деревья и другие элементы не должны стоять на дорогах. Город должен оставаться плотным и разнообразным, а ключевые объекты — различимыми. Существующий ЖК связан линиями со школой и детским садом.
- Не меняйте меню, текст и остальные блоки лендинга, если задача касается только иллюстрации.

## Где находятся исходники

Пути ниже указаны относительно корня проекта `current/`.

| Файл | Назначение |
| --- | --- |
| `site/src/isometric-hero.html` | Основная SVG-разметка, геометрия, ключевые объекты, тексты карточек и контейнер карточки. |
| `site/src/isometric-hero.css` | Стили сцены, постоянная и hover-подсветка, карточка, градиент, обрезка и адаптивные размеры. |
| `site/src/isometric-hero.js` | Генерация фоновой застройки, управление карточкой и её расположением. |
| `site/scripts/build.mjs` | Вставляет сцену на главную страницу, подключает CSS и JS и копирует их в сборку. |
| `docs/index.html`, `docs/isometric-hero.css`, `docs/isometric-hero.js` | Публикационная сборка GitHub Pages. Это результаты сборки, не основные исходники. |
| `docs/isometric-hero-v2-prototype.html` | Отдельный исторический прототип, если он есть в рабочей копии. Он не является источником публикационной сборки. |

Редактируйте прежде всего `site/src/`. Изменения только в `docs/` потеряются при следующей сборке. Обратно: изменения только в `site/src/` не появятся на GitHub Pages, пока не обновлена `docs/`.

## Устройство SVG

Сцена — встроенный `<svg id="territory" viewBox="-200 0 1400 850">`. Координаты объектов заданы в координатах этого `viewBox`, а не в пикселях экрана. CSS масштабирует сцену в шапке. Не меняйте `viewBox` для перемещения отдельного объекта: это изменит всю композицию и может нарушить размещение карточек.

Основные слои по порядку от заднего к переднему:

1. `<defs>` — повторно используемые формы зданий, деревьев и ключевых объектов. Экземпляры подключаются через `<use href="#…">` и собственный `transform`. Изменение формы в `<defs>` влияет на все её экземпляры.
2. `.grid`, участки `.parcel` и три слоя дорог: `.road`, `.road-surface`, `.road-mark`. Все три дорожных `path` используют одинаковую осевую геометрию.
3. Историческая группа статичной фоновой застройки с `display="none"`: она сохранена в разметке, но **не отображается**. Не рассчитывайте, что правки в ней изменят видимый город, и не включайте её без проверки пересечений.
4. `#background-city` — видимая фоновая застройка, создаваемая JavaScript. На ней `pointer-events="none"`, поэтому она не перехватывает наведение.
5. Линии связей `.data-link` и их точки — отдельные элементы, а не автоматические связи между объектами. Они не перехватывают указатель.
6. Шесть групп `.module` с участками и деталями ключевых объектов. Они размещены поверх фоновых слоёв; порядок SVG-групп влияет на перекрытие.

## Как изменить ключевой объект

Найдите нужную группу по `data-name`. Например:

```html
<g class="module school" transform="translate(478 151)"
   data-name="Школа"
   data-type="Социальная инфраструктура"
   data-description="Вместимость: 500 мест&#10;Занято сейчас: 440">
  <polygon class="module-base" points="…"/>
  <polygon class="module-top" points="…"/>
  <!-- детали школы -->
</g>
```

1. Для изменения внешнего вида редактируйте детали **внутри этой группы**. Если деталь создаётся через `<use>`, проверьте, используется ли соответствующий элемент `<defs>` в других местах.
2. Для перемещения всего объекта изменяйте `transform` внешней группы `.module`. Изменения координат внутренних деталей могут нарушить их взаимное положение. Сохраняйте ориентацию изометрии и проверяйте, что объект не пересекает дорогу и другие участки.
3. Сохраните `.module`, `.module-base`, `.module-top` и атрибуты `data-name`, `data-type`, `data-description`: они связывают рисунок, стили подсветки и содержимое карточки. Все видимые детали, с которых нужно вызывать карточку, должны оставаться внутри соответствующей группы `.module`.
4. При перемещении обновите вручную связанные с ним линии `.data-link` и точки: они не следуют за объектом автоматически. Также проверьте и при необходимости скорректируйте соответствующую зону исключения в массиве `landmarks` в JS.
5. Сверьте положение на широком и узком экране: края иллюстрации обрезаются, а слева действует маска. Не ориентируйтесь только на координаты SVG.

### Данные карточек

`data-name` — заголовок карточки, `data-description` — её текст, `data-type` — подпись типа в скрытом `#module-type`. Перенос строки в атрибуте записывается как `&#10;`; CSS карточки использует `white-space: pre-line`. Скрипт подставляет значения через `textContent`, поэтому HTML-разметка внутри атрибута не отобразится как форматирование.

Текущие цифры — демонстрационные, придуманные для связанного примера; в карточках они не помечены как условные. Не выдавайте их за проверенные данные и не добавляйте фактические утверждения без источника и согласования. Если меняете цифры, проверьте согласованность между ЖК, школой, садом и паркингом, включая суммы и дефицит.

## Фоновый город и дорожная сеть

`site/src/isometric-hero.js` детерминированно расставляет объекты в `#background-city`:

- `types` — варианты объектов из `<defs>`, их масштаб, опорная точка и приблизительный радиус занимаемой площади;
- `roads` — отрезки осей дорог для проверки дистанции до них;
- `landmarks` — приблизительные зоны вокруг ключевых объектов, которые фон должен обходить;
- `occupied` — проверка расстояний между фоновыми объектами; затем объекты сортируются по `y` для порядка отрисовки.

Если меняете геометрию дороги в SVG, синхронизируйте все три дорожных `path` **и** массив `roads` в JS. Если переносите ключевой объект, синхронизируйте `landmarks`: это вручную заданные приближённые зоны, а не вычисляемые границы SVG. Проверка расстояний приблизительная и не доказывает отсутствие визуальных пересечений, особенно у высоких или необычных форм. Обязательно осмотрите результат и при необходимости поправьте радиусы, опорные точки, исключения и сами объекты.

При добавлении фонового типа создайте или используйте `<g id="…">` в `<defs>`, добавьте его описание в `types` и проверьте наземное пятно, дорожные зазоры и порядок перекрытия. Не размещайте в `#background-city` интерактивные модули: у слоя отключены события указателя.

## Подсветка и расположение карточки

CSS задаёт постоянную цветную рамку `.module-base` и изменение `.module-base`/`.module-top` при `:hover` или `.is-active`. Детали отдельных объектов могут иметь собственные SVG-цвета. Оранжевый контур не должен исчезать в исходном состоянии.

Скрипт один раз собирает группы `.module` после загрузки страницы, слушает `mouseenter` и `mouseleave`, переключает `.is-active`, заполняет одну общую `.callout` и вычисляет её позицию по `getBoundingClientRect()` объекта и `.scene-card`. При изменении размера окна положение открытой карточки пересчитывается. Карточка имеет `pointer-events: none`, чтобы не мешать уходу курсора с объекта. Не удаляйте или не переименовывайте `.callout`, `.scene-card`, `#module-name`, `#module-text`, `#module-type` без соответствующих изменений JS.

Текущее поведение — именно наведение мыши: отдельной логики касания, открытия по клику или клавиатурного фокуса нет. Не заявляйте, что она реализована. Если пользователь отдельно попросит полноценную доступность на сенсорных устройствах или с клавиатуры, согласуйте поведение и реализуйте его отдельно, не ломая согласованный hover-сценарий.

## Градиент и адаптивность

В `isometric-hero.css` контейнер `.scene-card` привязан к правой стороне шапки. Маска на `#territory` плавно скрывает SVG слева, позволяя тексту оставаться читаемым. При ширине до 1050 и до 760 пикселей используются отдельные правила; на узком экране маска отключается, сцена сдвигается вниз и обрезается границами шапки. Масштаб, маска и размеры контейнера влияют также на доступность участков и размещение бабблов. После изменения этих правил обязательно проверяйте каждую интерактивную область на соответствующем размере экрана.

## Сборка и проверка

Из каталога `site/`:

```bash
npm run build   # формирует site/dist/
npm run check   # проверяет сборку и сохранность содержания
npm run release # собирает, проверяет и копирует результат в docs/; не отправляет в GitHub
```

Сборка удаляет и заново создаёт `site/dist/`; не храните там единственные копии рабочих файлов. `release` копирует **всю** сборку в `docs/`, а не только иллюстрацию. До и после запуска проверяйте `git status` и `git diff`: если обнаружились несвязанные с задачей изменения или пользовательские файлы, не включайте их автоматически в публикацию и не затирайте пользовательскую работу. Проверки проекта полезны, но не заменяют визуальную проверку и проверку наведения.

Минимальная ручная проверка:

1. Откройте собранную страницу с включённым JavaScript и проверьте консоль на ошибки. Без JS процедурная застройка и бабблы не работают.
2. Убедитесь, что изначально все шесть участков заметны, а карточек нет. Наведите на каждый из шести, проверьте заголовок, текст, переносы и подсветку; отведите курсор — карточка исчезает. Клик не должен выполнять действие.
3. Проверьте карточки у границ сцены, при изменении ширины окна и при длинном тексте: они должны оставаться читаемыми и не обрезаться. Отдельно осмотрите мобильную компоновку; имейте в виду отсутствие сценария касания.
4. Осмотрите все дороги и ключевые участки: фоновые здания и деревья не стоят на дороге и не перекрывают ключевые объекты; линии связей заканчиваются в нужных местах; город заполняет сцену без пустой нижней полосы.
5. Сверьте градиент, расположение иллюстрации, меню и текст первого экрана с текущей версией сайта. Проверьте, что остальные страницы не изменились случайно.
6. Проверьте собранную `docs/index.html` и подключённые ею версии CSS/JS, а также итоговый состав изменений в Git. Не добавляйте в коммит все незакоммиченные файлы без разбора.

Публикация на GitHub — отдельное действие. Следуйте действующим правилам проекта и требованию согласовать готовый результат с Михаилом до внешней публикации; запуск `release` сам по себе сайт не публикует.
